# 访谈清单

目的：问清楚"这个工作台要防哪些事、要积累什么"。不是填表，问到能推出蓝图就停。

## 问法规矩

- 用户给了资料，先读资料，只问读不出来的。
- 资料是课程、讲义、转录稿这类"别人的方法"时，先按 `资料提炼.md` 出提炼报告。提炼报告能回答第 2、4、5 组的大部分问题，访谈只补用户本人的情况（第 1、3、6、7 组）。
- 每轮最多问 3 个，先问会改变架构的（第 1、2、5 组），细节放后面。
- 用户答不上来的，不追着问，写"未知，先按 X 处理"。
- 用户给的答案太抽象（比如"提高效率"），追问一个**最近一次真实发生的例子**：上次做这件事是什么时候、做了什么、哪一步最费劲、哪一步最容易出错。

## 七组问题

| 组 | 问什么 | 决定蓝图里的什么 |
|---|---|---|
| 1. 领域和服务对象 | 这个工作台服务谁（自己、某个客户、一个团队、一个产品）？这个对象有哪些长期不变、但会影响判断的特点？ | 要不要档案；档案里放哪些字段 |
| 2. 反复做的工作 | 最常做的 3–5 件事是什么？每件多久做一次？有没有固定做法？做砸过吗，砸在哪？ | 技能清单；哪些是轻量指令 |
| 3. 输入 | 这些工作的原料从哪来（用户粘贴、文件、外部系统、网上公开数据）？有没有需要登录的系统？ | 原始资料目录；外部数据边界；有没有工具型技能 |
| 4. 产出 | 交付什么（文档、清单、判断、文件）？给谁看？什么时候算定稿？ | 产物目录；定稿触发语；输出格式 |
| 5. 怎么算做好 | 做得好和做得差，差在哪里？结果能不能观察到？多久能看到结果？ | 要不要反馈闭环；规律文件；目标成熟度 |
| 6. 红线 | 有什么绝对不能做的（泄密、对外发送、改动线上数据、替人做决定）？有没有要和日常工作隔开的话题？ | 边界与隔离 |
| 7. 环境 | 用哪些 agent？工作台放在哪个目录？以后会不会有别人用？ | 入口文件名；技能源头和软链接；目录位置 |

另外留意一件事：用户的**说话方式和偏好**（喜欢多直接、讨厌什么样的表达、自身水平如何）。这决定入口文件里"你怎么说话"那一段怎么写，不用专门问，从对话里看。

## 访谈结论卡

访谈结束后输出这张卡，让用户确认。确认后它就是蓝图的依据。

```
## 访谈结论
- 领域：
- 服务对象：（谁；需要长期记住的特点）
- 反复做的工作：
  1. （名称）— 频率 / 现在怎么做 / 最常出错在哪
  2. …
- 输入来源：
- 产出与定稿：（交付什么；什么话算定稿）
- 做好的标准：（结果能否观察到、多久能看到）
- 红线：
- 需要隔离的话题：（没有就写"无"）
- 使用的 agent / 工作台位置：
- 未知项：（每项写"先按 X 处理"）
- 建议成熟度：L? —— 理由
```
