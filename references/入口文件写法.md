# 入口文件写法

入口文件（默认 `AGENTS.md`）是 AI 每次进来第一个读的东西。它只管四件事：**入口、路由、优先级、跨技能边界**。技能的执行细节不写在这里。

## 章节顺序

| 章节 | 写什么 | 不写什么 |
|---|---|---|
| 身份与原则 | 你是谁；你怎么工作（读 → 分析 → 交付）；你怎么说话 | 形容词堆砌 |
| 目录结构 | 一棵目录树，每个文件后面一句话写它干什么；写明技能的唯一源头和软链接 | 文件内容 |
| 技能是干什么的 | 每个技能用人话写 2–4 行，给用户和后来的维护者看 | 技能步骤 |
| 不用技能的几件事 | 轻量指令：触发语 → 动作 → 写到哪 → 不做什么 | — |
| 规则边界 | 文件职责边界：什么东西写在哪；raw / temp / output 规则和定稿触发语 | 某个技能内部的存档细节 |
| 优先级 | 用户当前要求 > 技能 > 入口文件；专项约定的位置 | — |
| 每次对话的工作流 | 第一步读档案（没有就建档）→ 第二步按路由表分流 → 第三步按技能执行 | — |
| 跨技能状态原则 | 档案、状态文件各自管什么；写权限表；专项约定（隔离、外部数据） | 技能内部的读写细节 |
| 输出原则 | 对所有产出都成立的 3–8 条要求 | 只对某个技能成立的要求 |

L0 工作台可以只有身份、目录、规则边界、优先级四节。

## 写法规矩

- **长度**：200–300 行以内。超了，说明执行细节漏进来了，挪回技能里。
- **路由表左边写用户原话的样子**，比如"帮我看看这份合同""这条款有没有坑"，不写"审查类需求"。
- **每条规则都能检查**：写成能看出有没有违反的行为，比如"没有说'定稿'不写 output/"，不写"注意产物管理"。
- **专项约定单独成段**：写日期、谁要求的、范围、为什么、和其他规则冲突时谁优先。
- **改过的规则就地写"YYYY-MM-DD 改：原因"**，作废的旧做法写明作废，免得残留在技能里的旧说法被执行。
- **说人话**：用户通常不是工程师。"技能是干什么的"那一节，要让用户读了就知道该说什么话来用它。

## 多 agent 兼容

- 内容只写在 `AGENTS.md`。
- 某个 agent 只认别的入口文件名时：放一个同名文件，只写"本工作台规则见 AGENTS.md"，或者用软链接。不要维护两份内容。
- 技能源头默认放 `.agents/skills/`，其他 agent 的技能路径用软链接指过去，并在目录结构里标注。
- 各 agent 实际读取哪个文件、哪个技能路径，以它当前的文档为准。不确定就先查，或者问用户。

## 常见坏法

| 坏法 | 后果 | 改法 |
|---|---|---|
| 技能步骤写进入口文件 | 改技能时忘了改入口，两边矛盾 | 入口只留一句指针 |
| 路由表有技能没有、或者技能没进路由表 | 用户说了话没人接 | 跑一遍 `检查清单.md` 的路由测试 |
| 输出原则写了 15 条 | AI 一条都记不住 | 只留最常被违反的几条 |
| 没写定稿触发语 | AI 自己决定什么时候算定稿 | 写死触发语，并写明哪些情况不算 |
